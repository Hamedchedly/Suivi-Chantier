# CAHIER DES CHARGES

## Application de pilotage et de suivi des chantiers de réhabilitation

### Version 1.0 — Septembre 2026

---

# 1. CONTEXTE

L'application `Suivi-Chantier` devient une application dédiée exclusivement au **pilotage des opérations de réhabilitation/construction**, depuis la préparation du chantier jusqu'à la réception et la levée des réserves.

Elle est **totalement indépendante de l'application de suivi de patrimoine**.

Il ne faut donc pas chercher à fusionner les deux applications.

L'application doit permettre de centraliser :

* opérations ;
* bâtiments ;
* logements/zones ;
* lots ;
* entreprises ;
* DPGF ;
* prestations ;
* planning ;
* avancement ;
* visites ;
* observations ;
* réserves ;
* photos ;
* documents ;
* CR de chantier ;
* RFI ;
* VISA ;
* marchés ;
* avenants ;
* situations ;
* suivi financier ;
* alertes et retards.

L'objectif n'est pas de créer un simple outil de compte-rendu.

L'objectif est de créer un **système de pilotage du chantier**, dans lequel le planning, le terrain, les documents et les données financières sont interconnectés.

# 3. PRINCIPES D'ARCHITECTURE

## 3.1 Une seule source de vérité

Supabase/PostgreSQL est la source de vérité.

Le frontend ne doit jamais contenir de données métier codées en dur.

Toutes les données doivent être rattachées à une `operation_id`.

---

## 3.2 Architecture multi-opérations

Une même instance doit pouvoir gérer :

* Gambetta ;
* Jean d'Orbais ;
* Sucy ;
* autres opérations futures.

Chaque opération possède ses propres :

* bâtiments ;
* logements ;
* lots ;
* entreprises ;
* tâches ;
* planning ;
* observations ;
* documents ;
* finances.

# 13. DRAG & DROP

Le Gantt doit permettre :

### Déplacement

Déplacer une tâche horizontalement = modifier sa date.

### Redimensionnement

Tirer le bord gauche/droit = modifier durée.

### Déplacement vertical

Changer de lot/swimlane.

### Multi-sélection

Déplacer plusieurs tâches ensemble.

### Snap

Accrochage au jour/semaine selon le niveau de zoom.

---

# 14. DÉPENDANCES

Supporter :

```text
FS — Finish to Start
SS — Start to Start
FF — Finish to Finish
SF — Start to Finish
```

Avec éventuellement :

```text
Lag +2 jours
Lag -1 jour
```

Le schéma Supabase actuel possède déjà une table `schedule_dependencies` et les quatre types de dépendance.

C'est donc une fonctionnalité à **finaliser**, pas à reconstruire conceptuellement.

# 15. CALENDRIER DE TRAVAIL

# 18. CHEMIN CRITIQUE / CPM

Implémenter un véritable moteur CPM.

Calculer :

* Early Start ;
* Early Finish ;
* Late Start ;
* Late Finish ;
* Total Float ;
* Free Float ;
* Critical Path.

Une tâche avec :

```text
Total Float = 0
```

est critique.

Ajouter :

**Afficher le chemin critique**

Les tâches critiques sont visuellement distinguées.

Le projet DingPlan identifie lui-même le CPM/critical path comme une fonctionnalité majeure de différenciation.
